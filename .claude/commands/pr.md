あなたはPRワークフロー管理のアシスタントです。ユーザーからのリクエスト「$ARGUMENTS」について、ブランチ作成からPRマージまでの一連のワークフローを実行します。

## PR ワークフローとは

このスキルは、以下の一連の作業を自動化します：
1. 最新のメインブランチから新しいブランチを作成
2. ユーザーが指定したタスクを実行
3. 変更をコミットしてプッシュ
4. Pull Requestを作成
5. PRをマージ（オプション）

## 使い方

`/pr <タスク内容>`

### 例

- `/pr ログイン機能にバリデーションを追加`
- `/pr README.mdのタイポを修正`
- `/pr 新しいAPIエンドポイントを追加`

## 実行手順

### Step 1: 準備（ブランチ作成）

1. 現在のブランチ状態を確認
   ```bash
   git status
   git branch --show-current
   ```

2. メインブランチ（main または master）を最新に更新
   ```bash
   git checkout main && git pull origin main
   ```

3. 新しいfeatureブランチを作成
   - ブランチ名は `feature/<タスクの概要を英語で>` の形式
   - 例: `feature/add-login-validation`
   ```bash
   git checkout -b feature/<branch-name>
   ```

### Step 2: タスク実行

1. ユーザーのリクエスト「$ARGUMENTS」を分析
2. 必要なファイルの調査と変更を実行
3. テストがある場合は実行して通ることを確認
4. リンターやフォーマッターがあれば実行

### Step 3: コミット＆プッシュ

1. 変更をステージング
   ```bash
   git add -A
   ```

2. 変更内容に基づいてコミットメッセージを作成
   - Conventional Commitsに従う（feat:, fix:, docs:, refactor: など）
   ```bash
   git commit -m "<type>: <description>"
   ```

3. リモートにプッシュ
   ```bash
   git push -u origin <branch-name>
   ```

### Step 4: Pull Request作成

1. PRを作成
   ```bash
   gh pr create --title "<PRタイトル>" --body "<PR説明>"
   ```

2. PRのURLをユーザーに報告

### Step 5: PRマージ（ユーザー確認後）

1. ユーザーにマージして良いか確認
2. 承認されたらマージを実行
   ```bash
   gh pr merge --squash --delete-branch
   ```

3. ローカルのメインブランチを更新
   ```bash
   git checkout main && git pull origin main
   ```

## 注意事項

- **マージ前の確認**: PRをマージする前に、必ずユーザーに確認を取る
- **コンフリクト**: マージコンフリクトが発生した場合は、ユーザーに相談する
- **CI/CD**: CIチェックが失敗した場合は、修正してから再度プッシュ
- **レビュー**: レビューが必要な場合は、マージせずにPR作成までで止める

## エラー時の対応

### プッシュ失敗時
```bash
git pull --rebase origin <branch-name>
git push
```

### マージコンフリクト時
1. コンフリクトしているファイルを確認
2. ユーザーと相談して解決方法を決定
3. 解決後、再度コミット＆プッシュ

### CIチェック失敗時
1. 失敗したチェックの内容を確認
2. 必要な修正を実施
3. 追加コミットをプッシュ

## オプション機能

- `--no-merge`: PR作成までで止める（マージしない）
- `--draft`: ドラフトPRとして作成
- `--reviewer <username>`: レビュアーを指定

### 例
- `/pr --no-merge バグ修正` - PR作成まで
- `/pr --draft 新機能のプロトタイプ` - ドラフトPRとして作成
