## Deep Research とは

Deep Researchは、単発の検索ではなく**反復的な調査プロセス**を通じて、複数の情報源から深く掘り下げた調査を行う手法です。質問を小さなタスクに分解し、検索→検証→追加検索のサイクルを繰り返すことで、人間が数時間かけて行うような調査を効率的に実行します。

## 調査の4段階プロセス

### Phase 1: 計画（Planning）

1. **調査対象の明確化**
   - ユーザーの依頼内容を分析
   - 調査の主題、目的、範囲を特定
   - 不明点があれば質問して明確にする

2. **調査計画の作成**
   - 質問を複数の小さな調査タスクに分解
   - どのような情報源を調べるべきか計画
   - 調査の優先順位を設定

### Phase 2: 探索（Exploration）

**初回検索**
- WebSearchで広範囲に情報を収集
- 複数の検索クエリを使い、異なる角度から調査
- 見つかった重要なページはWebFetchで詳細を取得

**反復検索（これが重要）**
- 初回検索で「足りない点」を自動判定
- 新しい検索キーワードを生成して再探索
- 矛盾する情報があれば追加検索で確認
- このサイクルを2〜3回繰り返す

### Phase 3: 推論（Reasoning）

1. **情報の検証**
   - 収集した情報の信頼性を評価
   - 公式ソースか、最新か、複数ソースで確認できるか
   - 矛盾する情報を識別し、どちらが正しいか判断

2. **情報の統合**
   - 異なるソースからの情報を統合
   - 重要なポイントを抽出
   - 全体像を構築

### Phase 4: 報告（Reporting）

構造化されたレポートを作成し、すべての出典を明記する。

## 反復検索の実践例

```
【初回検索】
「React Server Components メリット」で検索
→ 概要は分かったが、パフォーマンスの具体的な数値が不足

【2回目検索】
「React Server Components performance benchmark 2024」で検索
→ ベンチマーク結果を発見。しかしデメリットの情報が不足

【3回目検索】
「React Server Components デメリット 課題 制限」で検索
→ 課題や制限事項を発見

【統合】
すべての情報を統合してバランスの取れたレポートを作成
```

## 調査タイプ別のアプローチ

### 一般的なトピック調査
```
初回: Wikipedia、公式サイトで概要把握
追加: 専門家の見解、最新ニュース
検証: 複数ソースで事実確認
```

### ビジネス・市場調査
```
初回: 業界レポート、市場規模
追加: 競合情報、トレンド分析
検証: 政府統計、調査会社データ
```

### 学術・研究調査
```
初回: 学術論文、研究機関レポート
追加: 関連研究、最新の発表
検証: 査読済み論文、引用数
```

### 製品・サービス調査
```
初回: 公式サイト、製品仕様
追加: レビュー、比較記事
検証: ユーザー評価、実使用レポート
```

### 技術・プログラミング調査
```
初回: 公式ドキュメント、GitHub
追加: 技術ブログ、ベストプラクティス
検証: Stack Overflow、実装例
```

### 時事・ニュース調査
```
初回: 主要ニュースサイト
追加: 専門メディア、関係者の発言
検証: 複数メディアでのクロスチェック
```

### 地域・文化調査
```
初回: 観光局、自治体公式サイト
追加: 旅行サイト、体験記事
検証: 現地メディア、専門書籍
```

## 調査のベストプラクティス

1. **複数回の検索を必ず実行**: 1回の検索で満足せず、最低2〜3回は異なる角度から検索
2. **情報の空白を埋める**: 「足りない情報は何か」を常に意識し、追加検索で補完
3. **矛盾の解消**: 異なる情報源で矛盾があれば、追加調査で確認
4. **信頼性の評価**: 各情報の信頼性を評価し、レポートに反映
5. **出典の明記**: すべての情報に出典を付け、検証可能にする
6. **限界の明示**: 確認できなかった点は正直に記載

## 注意事項

- 著作権に配慮し、引用元を必ず明記する
- 機密情報や個人情報を含む検索は避ける
- 調査に時間がかかる場合は、進捗を報告する
- 意見が分かれるトピックでは、複数の視点を公平に紹介する
- ハルシネーション（事実に基づかない情報の生成）を防ぐため、必ず出典を確認する
